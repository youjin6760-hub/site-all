다음 문제 데이터를 형식 기준으로만 검수해줘.

중요:
내용(정답, 문제 성립 여부, 해설 논리)은 절대 검수하지 않는다.
형식만 검수한다.

---

[검수 항목]

1. 해설 시작 문장

반드시 아래 패턴 형식을 따라야 한다.

정답은 [숫자]번입니다.

정상 예:
- 정답은 1번입니다.
- 정답은 2번입니다.
- 정답은 3번입니다.
- 정답은 4번입니다.

여기서 [숫자]는 실제 정답 번호를 의미하며,
문자 그대로 "X번"이 들어가야 한다는 뜻이 아니다.

---

[해설 시작 형식 오류 단일 기록 규칙]

해설 첫 문장이 "정답은 [숫자]번입니다." 형식이 아닌 경우,
동일 문제에서는 반드시 "해설 시작 형식 오류" 1개만 기록한다.

다음 표현들은 모두 같은 원인의 오류로 본다.
- explanation 시작 형식 오류
- 해설 시작 문장 오류
- 첫 문장 형식 오류
- "답은 X번입니다." 사용
- "정답은 X번입니다." 형식과 불일치

위 내용을 기타 형식 오류, 최종 문장 형식 오류, 표현 오류로 중복 기록하지 않는다.

reason에는 실제 시작 문장만 적는다.
suggestion에는 수정 형식 1개만 적는다.

---

2. 선지별 해설 존재 여부
- 각 선지에 대한 설명이 존재해야 한다

---

3. 선지 해설 형식

일반 문제:
- 반드시 "X. 선지 전체 문장" 형식

예외 (다음 경우 허용):
- 선지가 이미지인 경우
- 선지가 너무 긴 경우

→ 이 경우 "X. 선지 X" 허용

---

[해설 문체 검수 규칙]

문체 검수는 explanation 원문에만 적용한다.
문제 본문, 보기, 선지, extra_text, choices에는 적용하지 않는다.

해설은 반드시 존댓말 문어체로 작성되어야 한다.

정상 표현:
- ~입니다.
- ~합니다.
- ~됩니다.
- ~습니다.
- ~하고 있습니다.
- ~할 수 있습니다.
- ~라고 볼 수 있습니다.
- ~에 해당합니다.
- ~를 의미합니다.
- ~하게 됩니다.
- ~하게 되므로
- ~해야 합니다.
- ~볼 수 있습니다.

다음과 같은 평서체/반말/구어체 표현이 explanation 원문에 있으면 반드시 "기타 형식 오류"로 기록한다.

오류 표현:
- ~이다.
- ~된다.
- ~한다.
- ~의미한다.
- ~해당한다.
- ~설명한다.
- ~나타낸다.
- ~볼 수 있다.
- ~알 수 있다.
- ~임
- ~됨
- ~같음
- ~거임
- ~아님
- ~있음

중요:
- 문제 본문, 보기, 선지에 있는 평서체는 오류로 판단하지 않는다.
- choices의 문장을 해설에서 그대로 인용한 경우는 예외로 한다.
- SQL, 함수명, 컬럼명, 테이블명, 키워드는 예외로 한다.
- 문체 오류가 여러 문장에 있어도 동일 문제에는 1개의 오류만 기록한다.
- reason에는 explanation 원문에서 확인된 대표 사례 1~2개만 작성한다.

---

[문체 오류 중복 기록 금지]

존댓말/평서체 규칙 위반이 여러 문장에서 발견되더라도 동일 문제에 대해 1개의 오류만 기록한다.

예:
- ~이다
- ~된다


이 여러 번 등장해도 각각 따로 기록하지 않는다.

reason에는 대표 사례 1~2개만 작성한다.

---

[부정형 문제 처리 규칙]

문제에서 다음 표현이 있으면 부정형 문제로 판단한다.

- 옳지 않은 것은?
- 틀린 것은?
- 적절하지 않은 것은?
- 바르지 않은 것은?

부정형 문제에서는 정답 선지를 "틀린 설명", "부적절한 설명", "옳지 않은 설명"이라고 해설하는 것이 정상이다.

따라서 정답 선지 해설에서
- 틀린 설명입니다
- 옳지 않습니다
- 부적절합니다
- 정답입니다

가 함께 등장해도 오류로 판단하지 않는다.

단, 정답 번호가 서로 다르거나 다른 선지 내용을 설명하는 경우에만 오류로 판단한다.

4. 선지 해설 구조

- "X. ..." 다음 줄 ":" 구조인지 확인

예:
1. 선지 내용
: 설명

5. 결론 문장

- 반드시 마지막에 존재해야 한다.

- "따라서,"와 "따라서"는 모두 정상으로 인정한다.
- 즉, 따라서 뒤의 쉼표(,) 누락은 오류가 아니다.
- 작은따옴표 종료 후 "입니다." 앞 공백은 정상으로 인정한다.

일반 문제:
따라서, 정답은 'X. 실제 정답 선지 원문' 입니다.
또는
따라서 정답은 'X. 실제 정답 선지 원문' 입니다.

축약 문제:
따라서, 정답은 'X. 선지 X' 입니다.
또는
따라서 정답은 'X. 선지 X' 입니다.

정상 인정 예시:
- 따라서, 정답은 '3. 하나의 속성은 여러 개의 값을 동시에 가질 수 있으며, 이를 통해 다양한 값을 표현할 수 있다.' 입니다.
- 따라서 정답은 '3. 하나의 속성은 여러 개의 값을 동시에 가질 수 있으며, 이를 통해 다양한 값을 표현할 수 있다.' 입니다.
- 따라서, 정답은 '1번' 입니다.
- 따라서 정답은 '1번' 입니다.

---
[기호/짧은 선지 결론 문장 허용 규칙]

선지 자체가 기호, 함수명, SQL 키워드, 짧은 값으로 구성된 경우에는 결론 문장에도 해당 선지 그대로 들어가면 정상으로 인정한다.

정상 예:
- 선지: =
  결론: 따라서, 정답은 '3. =' 입니다.

- 선지: <>
  결론: 따라서 정답은 '2. <>' 입니다.

- 선지: NULL
  결론: 따라서, 정답은 '4. NULL' 입니다.

- 선지: INNER JOIN
  결론: 따라서, 정답은 '1. INNER JOIN' 입니다.

다음 경우는 오류가 아니다.
- 선지 전체가 기호 1개인 경우
- 선지 전체가 짧은 SQL 키워드인 경우
- 선지 전체가 함수명 또는 연산자인 경우
- 선지 원문 자체가 짧아서 결론 문장도 짧은 경우

중요:
결론 문장 안의 정답 표기가 choices의 실제 정답 선지와 정확히 일치하면 오류로 판단하지 않는다.
"선지 전체 문장"이 길어야 한다고 판단하지 않는다.

---

[결론 문장 따옴표 허용 규칙]

결론 문장 검수 시, 선지 원문을 보존하기 위해 발생하는 아래의 케이스들은 절대 오류로 판단하지 않는다.

1. 따옴표 중첩 및 인접 허용:
   - 선지 내용 자체에 따옴표가 있어 결론 문장의 감싸기용 따옴표와 중첩되는 경우 (예: '... 'A' ...' 와 같이 따옴표가 연속되거나 겹치는 경우)
   - 따옴표 안에 또 다른 따옴표가 포함되어 '' 또는 "" 형태가 나타나는 경우

2. 선지 원문 보존 우선:
   - 선지 내부에 포함된 작은따옴표('), 큰따옴표("), SQL 문자열, 컬럼명, 용어 강조용 기호 등은 모두 정상으로 간주한다.
   - 선지 원문에 포함된 기호로 인해 전체 따옴표 개수가 짝수가 아니게 되거나, 문장 구조가 복잡해 보여도 선지 텍스트가 정확히 인용되었다면 정상이다.

3. 미세 형식 허용:
   - 따옴표 종료 후 "입니다." 앞에 공백이 있는 경우 ('선지' 입니다.)
   - '따라서' 뒤에 쉼표(,)가 누락된 경우
   - 결론 문장 내에서 강조를 위해 작은따옴표가 여러 번 사용된 경우

[최종 문장 형식 오류 기록 금지 사항]
- 단순히 "따옴표가 많다"거나 "중첩되어 보기 어색하다"는 주관적 이유로 이슈를 생성하지 마라.
- 선지의 특수문자나 기호를 제거하라고 수정 제안(suggestion)하지 마라. (원문 보존이 원칙)


---

6. 정답 문장 중복

- 해설 중간 또는 결론 이전에
  "정답은 X번입니다."가 다시 나오면 오류

[정답 문장 중복 오류 단일 기록 규칙]

"정답은 X번입니다."가 해설 시작 문장 외 위치에 반복 등장하는 경우,
동일 문제에서는 반드시 "정답 문장 중복" 1개만 기록한다.

이 오류를 다음 type으로 중복 기록하지 않는다.
- 해설 시작 형식 오류
- 기타 형식 오류
- 최종 문장 형식 오류

reason에는 반복 등장한 정답 문장 1개만 대표로 작성한다.

---

7. 최종 문장 형식 오류

다음이 있으면 오류:
- :, ;, , ... 등 잔여 기호
- 불필요한 괄호
- 선지 원문에 존재하지 않는 불필요한 중복 따옴표
단, 선지 원문 자체에 작은따옴표(') 또는 큰따옴표(")가 포함되어 결론 문장에 그대로 반복되는 것은 중복 따옴표 오류가 아니다.

---

[따옴표 검수 제한 규칙]

작은따옴표(')는 SQL 문자열, 용어 인용, 선지 원문, 해설 설명에서 자연스럽게 사용될 수 있다.

따라서 다음만 오류로 판단한다.

1. 작은따옴표 때문에 문장이 명확히 깨져 의미 파악이 불가능한 경우
2. 결론 문장에서 정답 선지 부분이 따옴표 오류로 인해 누락되거나 잘린 경우
3. HTML/Markdown 렌더링상 화면에 따옴표가 깨진 문자로 노출된 경우

다음은 오류로 판단하지 않는다.
- 작은따옴표 개수가 홀수인 경우만으로 오류 처리
- 선지에 작은따옴표가 포함된 경우
- 보기/선지/해설에 작은따옴표가 여러 번 등장하는 경우
- SQL 예시에서 '값' 형태가 사용된 경우
- 용어를 '데이터 모델링'처럼 감싼 경우

중요:
따옴표 검수는 기계적으로 개수를 세지 말고, 실제 문장 의미와 렌더링 문제가 있는 경우에만 오류로 기록한다.

---

[원문 근거 필수 규칙]

오류 reason에는 반드시 explanation 원문에서 확인 가능한 실제 문자열을 기준으로 작성한다.

예:
- 실제 원문에 "3 .관계는"이 있을 때만 오류
- 실제 원문에 "3. 관계는"으로 정상 작성되어 있으면 오류 금지
- 실제 원문에 ":" 구조가 정상 존재하면 오류 금지

원문에 없는 문자열을 만들어서 오류로 기록하지 않는다.

---

8. 표현 오류

다음 문자열이 explanation 원문에 하나라도 포함되면 반드시 "기타 형식 오류"로 기록한다.

- 백틱(`)
- Markdown 굵게 표시 문법인 **

판단 기준:
- explanation 안에 **가 1개라도 있으면 오류
- **정답**, **해설**, **키워드**처럼 강조용으로 사용된 경우도 오류
- 사용자 노출용 해설에는 Markdown 문법을 허용하지 않는다.

예외:
- 없음

---

9. 긴 해설 검수

조건:
explanation_capture_meta.capture_mode = "too_long_after_zoom"

→ 반드시 아래 format_issues 추가

{
 "type": "긴 해설 수동 검토 필요",
 "reason": "해설 스크린샷 없이 긴 해설 텍스트만 제공되어 수식/표현 검증에 제한이 있습니다.",
 "suggestion": "수동 검토를 통해 수식 및 렌더링 상태를 확인하세요.",
 "confidence": 0.7
}

---

[오류 기록 전 필수 확인 규칙]

오류를 기록하기 전 반드시 실제 explanation 원문에 해당 오류 문자열 또는 형식 문제가 존재하는지 확인한다.

다음 경우는 오류로 기록하지 않는다.

1. 실제로 문제가 없다고 판단한 경우
- "정답은 일치합니다"
- "오류는 없습니다"
- "정답값은 유지해도 됩니다"
- "수정할 필요는 없습니다"

위와 같이 정상이라고 판단되는 내용은 절대 issue로 작성하지 않는다.

2. 추정 금지
- "보입니다"
- "가능성이 있습니다"
- "어색해 보입니다"
- "완전히 일치하지 않는 부분이 있습니다"
처럼 추정에 기반한 오류는 기록하지 않는다.
명확히 원문에서 확인된 오류만 기록한다.

---

[정상 판단 issue 기록 금지]

오류가 없으면 content_issues 또는 format_issues에 절대 항목을 추가하지 않는다.

다음 표현이 포함되는 판단은 issue가 아니라 정상 판단이므로 기록하지 않는다.

- 오류는 없습니다
- 형식 오류는 없습니다
- 문제는 없습니다
- 이상 없습니다
- 정상입니다
- 일치합니다
- 불일치는 없습니다
- 해당 없음
- 수정할 필요 없습니다
- 유지해도 됩니다
- 문제 없어 보입니다
- 확인 가능한 오류는 없습니다

중요:
reason 또는 suggestion에 위 표현이 들어가는 issue는 생성하지 않는다.
오류가 없으면 반드시 빈 배열 []로 반환한다.

---
[출력 스키마]

{
 "question_id":"",
 "content_issues": [],
 "format_issues": [],
 "summary":{
   "has_issue": false,
   "severity":"low"
 }
}

오류가 있을 경우:

{
 "type":"",
 "reason":"",
 "suggestion":"",
 "confidence":0.0
}

규칙:
- format_issues.type은 아래 중 하나만 사용
해설 시작 형식 오류
선지별 해설 누락
선지 해설 형식 오류
정답 문장 중복
결론 누락
최종 문장 형식 오류
기타 형식 오류
긴 해설 수동 검토 필요

- 형식 오류만 있는 경우 severity는 low 또는 medium
- 하나라도 오류가 있으면 has_issue = true
