다음 문제 데이터를 검수해줘.

[최우선 검수 단계 - 반드시 먼저 수행]
다른 모든 검수보다 먼저 아래를 판단한다.

1. 문제 성립 여부
2. 정답(answer) 검증
3. 해설 논리 검증

이 단계에서 오류를 발견하면 반드시 content_issues에 기록해야 하며,
이 검수를 수행하지 않고 다른 검수만 수행하면 잘못된 출력이다.

---

[문제 성립 오류 판단 규칙 - 최우선]

다음 중 하나라도 해당하면 반드시 "문제 성립 오류"로 기록한다.

1. 문제를 풀기 위해 필요한 정보가 누락된 경우
2. 문제 이미지 또는 선지 이미지가 없거나 잘못되어 문제 풀이가 불가능한 경우
3. 문제에 제시된 표, ERD, SQL 결과, 수식 등이 없어서 정답 도출이 불가능한 경우
4. 문제의 SQL, 수식, 정규표현식이 깨져서 해석이 불가능한 경우
5. 문제 본문/보기/이미지에 존재하지 않는 속성, 컬럼, 엔터티를 기준으로 정답을 요구하는 경우

중요:
이미지 문제의 경우 반드시 아래를 판단한다.

- 이미지 없이 문제 풀이가 불가능하면 반드시 "문제 성립 오류"

이 경우 "이미지 불일치"가 아니라 "문제 성립 오류"로 판단한다.

---

[이미지 렌더링 오류 검수 규칙]

문제 이미지, 선지 이미지, 표 이미지, ERD 이미지, 수식 이미지가 존재하는 경우 반드시 아래를 검사한다.

다음 경우 반드시 "문제 성립 오류"로 기록한다.

- 이미지가 깨져 보이는 경우
- 이미지 일부가 잘린 경우
- 이미지 해상도가 낮아 핵심 내용을 읽을 수 없는 경우
- 수식/SQL/표/ERD 일부가 보이지 않는 경우
- 이미지 로딩 실패 흔적이 있는 경우
- 빈 이미지 또는 비정상적으로 작은 이미지인 경우
- 선지 이미지가 다른 문제 이미지로 보이는 경우
- 문제 설명과 이미지 내용이 서로 다른 경우

중요:
이미지가 정상적으로 첨부되어 있더라도, 실제 문제 내용이 아닌 '문제에 포함된 이미지' 같은 대체 텍스트/placeholder만 보이면 반드시 "문제 성립 오류"로 기록한다.

이미지 없이는 정답 판단이 불가능한데 이미지가 깨졌거나 누락된 경우 반드시 "문제 성립 오류"로 기록한다.


[이미지 기반 문제 강제 검수]

문제, 보기 이미지가 포함된 문제는 반드시 실제 이미지 내용을 기준으로 검수한다.

텍스트만 보고 정상이라고 판단하지 않는다.

이미지 안에 다음과 같은 placeholder 문구만 존재하는 경우 반드시 문제 성립 오류로 판단한다.

예:
- 에 포함된 이미지
- image
- no image
- loading
- broken image
- failed to load

중요:
실제 문제 내용 없이 placeholder UI만 보이는 이미지는 정상 문제 이미지가 아니다.

---

[내용 검수]

- 문제와 정답(answer)이 일치하는지
- 정답(answer), 해설 시작 문장, 해설 마지막 문장의 정답 번호가 서로 일치하는지
- 해설이 논리적으로 맞는지
- 오답 설명이 올바른지
- 문제와 해설의 SQL, 수식, 조건식, 컬럼명, 테이블명이 일치하는지

---

[해설 적절성 검수 규칙]

해설이 단순히 정답 번호만 맞는지가 아니라, 실제 문제의 핵심 개념과 풀이 과정을 올바르게 설명하는지 검수한다.

다음 경우 반드시 "해설 내용 오류"로 기록한다.

- 해설이 문제 핵심 개념과 다른 내용을 설명하는 경우
- 정답 근거 설명이 부족한 경우
- 왜 오답인지 설명하지 않는 경우
- 문제 조건을 사용하지 않고 일반론만 설명하는 경우
- 문제의 SQL/ERD/수식/조건과 무관한 설명을 하는 경우
- 해설만 읽어서는 정답 도출 과정이 이해되지 않는 경우

중요:
정답 번호만 맞아도 해설이 부적절하면 정상 처리하지 않는다.

---

[문제-해설 불일치 검수 규칙]

- 문제 본문/extra_text/보기/이미지의 핵심 표현과 해설의 풀이 기준이 다르면 반드시 "해설 내용 오류"로 기록한다.

특히 다음은 무조건 오류:
1. 문제 SQL과 해설 SQL이 다른 경우
2. 문제 수식과 해설 수식이 다른 경우
3. 문제 조건과 해설 조건이 다른 경우

---

[정답 관련 오류 규칙]

- answer 값이 실제 정답과 다르면 "정답 불일치" 1개만 기록한다.
- 이 경우 해설 오류는 별도로 기록하지 않는다.

---

[정답 불일치 기록 제한 규칙]

정답 불일치는 answer 값이 실제 정답과 명확히 다를 때만 기록한다.

다음 경우는 절대 정답 불일치로 기록하지 않는다.
- answer 값이 맞다고 판단한 경우
- 해설 시작 문장과 마지막 문장의 정답 번호가 answer와 일치하는 경우
- reason 안에서 "정답은 일치합니다", "정답 불일치는 없습니다", "정답값은 유지해도 됩니다"라고 판단되는 경우

정답이 일치하면 content_issues에 아무 항목도 추가하지 않는다.
정상 판단 내용을 issue로 작성하지 않는다.

---

[표현 오류]

다음이 있으면 반드시 "표현 오류"로 기록한다.

- 수식 깨짐
- 특수문자 깨짐
- 백틱(`) 사용
- Markdown(**) 잔여 문법
- 글리프(문자 형상) 변형

중요:
표현 오류는 내용 오류와 별도로 반드시 기록한다.

---

[선지-해설 강제 매칭 검수]

choices와 explanation의 선지별 해설을 반드시 번호 기준으로 1:1 비교한다.

- 번호가 같더라도 다른 선지를 설명하면 "선지-해설 불일치"
- 하나라도 불일치가 있으면 반드시 오류로 기록

---

[정상 판단 issue 기록 금지]

오류가 없으면 content_issues 또는 format_issues에 절대 항목을 추가하지 않는다.

아래 표현이 reason 또는 suggestion에 포함되면 해당 항목은 오류가 아니라 정상 판단이므로 절대 issue로 기록하지 않는다.

- 오류는 없습니다
- 형식 오류는 없습니다
- 문제는 없습니다
- 이상 없습니다
- 정상입니다
- 일치합니다
- 불일치는 없습니다
- 해당 없음
- 수정할 필요 없습니다
- 유지해도 됩니다
- 문제 없어 보입니다
- 확인 가능한 오류는 없습니다
- 문제 성립에는 문제가 없음
- 문제 성립 오류는 해소된다
- 문제 성립 오류가 아니다
- 이미지가 정상 첨부되어 있다
- 이미지가 정상적으로 렌더링되어 있다
- 정답 검증이 가능하다
- 정답이 올바르다
- 정답은 올바르다
- 권장
- 병기하는 것을 권장
- 명시하는 것을 권장

중요:
"권장" 수준의 개선 제안은 오류가 아니다.
오류가 명확하지 않고 개선 권장에 그치는 경우 content_issues에 기록하지 않는다.

---

[출력 스키마]

{
 "question_id":"",
 "content_issues": [],
 "format_issues": [],
 "summary":{
   "has_issue": false,
   "severity":"low"
 }
}

오류가 있을 경우:

{
 "type":"",
 "reason":"",
 "suggestion":"",
 "confidence":0.0
}

규칙:
- content_issues.type은 아래 중 하나만 사용
문제 성립 오류
정답 불일치
해설 내용 오류
선지-해설 불일치
표현 오류
기타 내용 오류

- summary.severity는 반드시 low / medium / high 중 하나
- 문제 성립 오류, 정답 불일치는 반드시 high
- content_issues 또는 format_issues가 하나라도 있으면 has_issue는 true
